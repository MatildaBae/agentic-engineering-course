## Compaction comparison

**Scope.** Evidence covers OpenClaw’s current documentation (retrieved 21 February 2025; no release/commit was supplied) and Codex CLI’s `main` source (retrieved 21 February 2025; no commit/version was supplied). “OpenClaw” is assumed to mean `openclaw/openclaw`; provider/configuration differences remain possible.

| | Codex CLI | OpenClaw |
|---|---|---|
| **Triggers** | Manual `/compact` is documented as squashing chat history. Source supports automatic compaction (`CompactionTrigger::Auto`) and distinguishes pre-turn, mid-turn, and post-turn phases. Exact threshold is not established by the collected evidence. ([Codex `codex-rs/core/src/compact.rs`](https://github.com/openai/codex/blob/main/codex-rs/core/src/compact.rs), retrieved 21 Feb 2025) | Automatic compaction is enabled by default when nearing the context limit or after a context-overflow error, followed by retry. `/compact` forces it. Proactive compaction can be disabled, but overflow recovery and manual compaction remain available. ([OpenClaw compaction docs](https://docs.openclaw.ai/concepts/compaction), retrieved 21 Feb 2025) |
| **What is retained** | The implementation creates a replacement history containing a compaction summary; pre-turn/manual compaction clears reference context so initial context is reinjected on the next regular turn. Mid-turn compaction injects initial context before the last real user message. A 20,000-token maximum applies to the compact user message. Exact summarization/drop rules are not shown in the collected excerpt. | Older conversation is summarized; a recent tail is retained, default `keepRecentTokens: 20,000`. Tool calls remain paired with matching results at split points. Summaries receive text, while image pixels are omitted and marked. Quality safeguards preserve required headings, pending asks, and exact identifiers where validation succeeds. |
| **Persistence/resume** | Source says compacted history and metadata are persisted via `replace_compacted_history`; Codex also maintains session JSONL, and collected issue evidence reports that it remains after failed compaction. Exact file format/resume semantics were not established. | Full conversation remains on disk; compaction changes only the next model-visible context. The compacted summary is saved in the session transcript. Pruning is distinct: it trims old tool results in memory per request and is not saved. |
